# Telegram Support Chat v2.2

Поддержка в Telegram без тикетов. Для пользователя бот выглядит как один постоянный личный диалог. Для модератора это временно отрисовываемое рабочее окно: он выбирает пользователя, видит историю, пишет обычным текстом/фото и может мгновенно переключиться на другой чат.

## Что реализовано

- один вечный диалог на каждого пользователя, без тикетов, закрытия и назначения;
- несколько модераторов могут одновременно открыть один и тот же чат и отвечать;
- любой обычный текст/фото модератора в открытом чате отправляется пользователю;
- пользователь видит псевдоним конкретного модератора (`🛡 Алекс`);
- ответы других модераторов появляются в открытом чате вживую;
- при выходе/переключении временно отрисованные сообщения удаляются из лички модератора;
- при повторном входе история восстанавливается из SQLite;
- 10 исходных сообщений на страницу, с навигацией по истории;
- текстовая история уплотняется до реального лимита Bot API в 4096 видимых символов после разбора HTML: внутри одного сообщения могут идти секции разных авторов с отдельными `👤/🛡` заголовками; фото всегда отдельно;
- если модератор сейчас открыл этот чат, каждое новое сообщение пользователя сразу дорисовывается в его текущую ленту без обновления/перерендера чата;
- 10-секундный debounce остаётся только для модераторов, у которых этот чат не открыт: им приходит одно компактное уведомление вместо спама по одному слову;
- разделы `Новые`, `Активные`, `Мои`, `Старые`;
- `Мои` = активные (<24 часов с последнего сообщения пользователя) диалоги, где именно этот модератор уже отвечал;
- бессрочный глобальный бан/разбан;
- карточка пользователя (`Инфо`);
- только текст и фото, остальные типы явно отклоняются;
- SQLite WAL + busy timeout для нормальной конкурентной работы;
- Alembic, venv-скрипты, тесты и карта проекта.

## Что означает «Новые»

Диалог попадает в `Новые`, если последнее сообщение пользователя новее последнего ответа поддержки либо поддержка ещё ни разу не отвечала. После реального ответа модератора текущий входящий пакет считается обработанным.

`Активные` — пользователь писал менее `ACTIVE_HOURS` назад (по умолчанию 24 часа).

`Старые` — последнее сообщение пользователя старше этого порога.

`Мои` — одновременно `Активные` и есть хотя бы один прошлый ответ текущего модератора этому пользователю.

Списки могут логически пересекаться: например, старый неотвеченный диалог остаётся `Новым` и одновременно является `Старым`.

## Статус прочтения

Обычный Telegram Bot API не предоставляет read receipt для личного сообщения бот → пользователь. Поэтому в v2.2 история **вообще не рисует псевдо-статусы доставки/прочтения**: ни `✓ отправлено`, ни маркер о последующем ответе пользователя.

## Временный чат модератора

Когда модератор открывает пользователя, бот создаёт в его личке временное представление истории. Все Telegram message IDs этого представления записываются в `moderator_view_messages`.

При переключении:

1. временные сообщения удаляются через Bot API;
2. активный пользователь в `moderator_sessions` меняется;
3. новая страница истории заново рендерится из БД.

Telegram ограничивает удаление обычных сообщений возрастом 48 часов, поэтому `VIEW_TTL_HOURS=23`: открытое рабочее окно автоматически очищается задолго до лимита. Если бот был выключен больше 48 часов, Telegram уже может не разрешить удалить старые сообщения — сама история в БД при этом не теряется.

## Установка

Требуется Python 3.11+.

### Linux/macOS

```bash
cp .env.example .env
# отредактируйте .env
./scripts/setup_venv.sh
./scripts/run.sh
```

### Windows PowerShell

```powershell
Copy-Item .env.example .env
# отредактируйте .env
.\scripts\setup_venv.ps1
.\scripts\run.ps1
```

`run` сначала выполняет `alembic upgrade head`, затем запускает long polling.

## Настройка `.env`

Главное поле:

```env
BOT_TOKEN=...
MODERATORS_JSON={"123456789":"Алекс","987654321":"Мария"}
```

Ключи `MODERATORS_JSON` — Telegram user ID модераторов. Значения — имена, которые увидит пользователь.

Каждый модератор должен хотя бы один раз открыть бота и нажать `/start`, иначе Telegram не позволит боту первым присылать ему уведомления.

## Работа модератора

1. `/start` или `/menu`.
2. Открыть `Новые`, `Активные`, `Мои` или `Старые`.
3. Выбрать пользователя.
4. Бот удалит старое рабочее окно и покажет до 10 исходных сообщений истории.
5. Любой обычный текст или фото отправляется выбранному пользователю.
6. Исходное сообщение модератора по возможности удаляется и сразу перерисовывается ботом как `🛡 Имя`, чтобы текущий вид совпадал с восстановленной историей.
7. Управление открытым чатом находится в обычной reply-клавиатуре под полем ввода: `Старее / страница / Новее`, `Инфо / Бан (Разбанить)`, `К спискам`. Эти системные нажатия перехватываются и пользователю не пересылаются.

Системные команды (`/start`, `/menu`, `/back`) пользователю не пересылаются.

## Уплотнение истории

На восстановленной странице сначала объединяются последовательные текстовые сообщения одного автора в логический блок. Затем соседние **текстовые блоки разных авторов тоже упаковываются в одно Telegram-сообщение**, пока готовый видимый текст после разбора HTML укладывается в лимит Telegram 4096 символов. Каждый автор остаётся визуально отделён своим заголовком и временем. Искусственных порогов 2800/3000/3900 больше нет.

Например, три секции `👤 пользователь → 🛡 Igor → 👤 пользователь` обычно будут одним Telegram-сообщением. Фото всегда отправляется отдельным сообщением и разрывает текстовый пакет. Исходные строки в SQLite при этом не объединяются и не изменяются.

## Дебаунс входящих

Каждое пользовательское сообщение **сразу** сохраняется отдельной строкой в `support_messages`. Склейка — только UI.

Если у модератора этот пользователь **уже открыт**, новое сообщение пользователя (текст или фото) дорисовывается сразу в текущую ленту. Бот не закрывает и не перерисовывает чат целиком. Это работает на любой открытой странице истории.

Для остальных модераторов действует `DEBOUNCE_SECONDS` (10 секунд): таймер переносится каждым новым сообщением пользователя, а после тишины приходит одно компактное уведомление с текстовым превью, количеством фото и кнопкой `Открыть диалог`.

Через 10 секунд бот также делает повторную попытку live-доставки в открытые чаты, если мгновенная отправка ранее не удалась. Если модератор успел реально ответить, уже обработанный входящий пакет не рассылается постфактум.

## База данных

Новая концепция несовместима с ticket-схемой v1, поэтому v2 использует чистую схему и по умолчанию файл `support_chat.db`.

Основные таблицы:

- `users`;
- `support_messages`;
- `moderator_participants`;
- `moderator_sessions`;
- `moderator_view_messages`;
- `audit_logs`.

Полная схема описана в `PROJECT_MAP.md`.

## Ограничения v2

- настоящий Telegram read receipt для bot → user недоступен;
- история хранится бессрочно, автоматического retention пока нет;
- бан — ручной и бессрочный, но модератор может разбанить через UI;
- приложение рассчитано на один процесс polling. Для горизонтального масштабирования debounce и per-moderator locks нужно вынести в Redis/очередь;
- временные сообщения старше 48 часов Telegram может отказать удалять; 23-часовой housekeeping минимизирует этот случай.
