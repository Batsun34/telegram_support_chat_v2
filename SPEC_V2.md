# SPEC V2.2 — persistent support chat

## Пользовательская модель

Пользователь не знает о тикетах, очередях, взятии в работу или закрытии. У него один постоянный личный диалог с ботом поддержки.

Поддерживаемый контент: текст и фото. Любой другой тип получает явный ответ о неподдерживаемом формате.

История не закрывается и не переоткрывается: она продолжается бессрочно.

## Модераторы

- модераторов несколько;
- закреплений нет;
- один пользователь может быть одновременно открыт у нескольких модераторов;
- обычный текст/фото модератора в выбранном чате отправляется пользователю;
- системные команды не пересылаются;
- пользователь видит псевдоним конкретного модератора;
- смена модератора пользователю отдельно не анонсируется;
- ответы одного модератора в реальном времени отрисовываются у других модераторов, которые смотрят тот же чат на последней странице.

## История и paging

- полная история хранится в SQLite;
- UI показывает 10 исходных сообщений на страницу;
- страница 1 — последние 10;
- более старые страницы доступны кнопками;
- последовательный текст одного автора склеивается в логический render block;
- соседние текстовые render blocks, в том числе от разных авторов, упаковываются в одно Telegram-сообщение до реального лимита 4096 видимых символов после разбора HTML;
- внутри упакованного сообщения каждый автор сохраняет отдельный заголовок `👤/🛡` и время;
- фото всегда отдельный render block и разрывает текстовую упаковку;
- крупные блоки дробятся только когда готовый видимый текст с заголовком действительно превышает лимит Telegram; исходное Telegram-сообщение не режется по внутренним порогам 2800/3000/3900.

## Переключение чатов

Модераторская личка используется как временное рабочее окно.

При входе бот рендерит историю от своего имени с заголовками:

- `👤 Пользователь`;
- `🛡 Псевдоним модератора`.

При выходе/переключении все message IDs рабочего окна удаляются. Исходные сообщения модератора после успешной отправки пользователю также по возможности сразу удаляются и рендерятся обратно ботом в едином формате.

`VIEW_TTL_HOURS=23` защищает от 48-часового ограничения Telegram на удаление.

## Входящие уведомления

Каждое входящее сохраняется отдельно сразу.

Если модератор уже открыл этого пользователя, каждое новое source message пользователя немедленно дорисовывается в его workspace без полного refresh/reopen. Это относится к любой открытой странице истории.

Debounce = 10 секунд после последнего сообщения пользователя применяется к модераторам, у которых этот чат не открыт. После тишины:

- открытым модераторам не отправлять compact notification; при необходимости повторно попытаться дорисовать непринятые live messages;
- остальным — одно компактное уведомление на burst;
- текст внутри burst склеить;
- фото не объединять в историю; в компактном уведомлении допустимо показывать количество фото и открывать их через историю.

Реальный ответ модератора завершает текущий pending burst, чтобы уведомление не пришло постфактум после уже данного ответа.

## Списки

### Новые
`last_user_message_at > last_support_message_at` или ответов поддержки ещё не было.

### Активные
Последнее сообщение пользователя менее 24 часов назад.

### Старые
Последнее сообщение пользователя более 24 часов назад.

### Мои
Диалог активный и текущий модератор хотя бы раз отвечал этому пользователю.

## Статус ответа

Telegram Bot API не даёт обычному боту достоверный read receipt пользователя. В UI не показываем псевдо-статусы доставки/прочтения и не выводим маркер `после этого пользователь ответил`.

## Управление открытым чатом

`Бан/Разбанить`, `Инфо`, `К спискам`, индикатор страницы и листание истории находятся в persistent reply keyboard. Тексты этих кнопок являются системными командами модераторского UI и никогда не пересылаются пользователю. Подтверждение бана также выполняется reply-кнопками.

## Бан

Модератор может бессрочно глобально забанить пользователя и разбанить его обратно. Забаненный пользователь не может отправлять новые сообщения в поддержку; бот отвечает сообщением об ограничении доступа.

## Информация

Карточка пользователя содержит:

- Telegram ID;
- username;
- имя;
- первый контакт;
- последнее сообщение пользователя;
- последний ответ поддержки;
- количество сообщений пользователя/поддержки;
- список модераторов, которые отвечали;
- состояние бана.
